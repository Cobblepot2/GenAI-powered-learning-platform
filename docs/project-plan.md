# LearnLoop 项目计划与第 8/9 周讨论范围

LearnLoop 是面向软件工程学习者的互动微课平台。学习者完成短场景、作出选择、查看解释并记录进度；教师可以快速准备和编辑微课。第 8/9 周的目标是用可操作原型说明方案、范围和后续验证方式。

> 证据边界：本次原型与材料由 AI 辅助搭建，不代表团队已经完成对应开发或调研。真实贡献、访谈结果与课程要求中的疑点均待补充。本阶段按要求暂不安排或展示人员分工。

## 本阶段交付

- 本地可运行的浏览器原型，以及供课堂演示使用的三门内置微课。
- 1–2 页讨论摘要、约 6 分钟演示脚本、架构说明和迭代路线。
- 可执行的用户验证计划，以及待导入 GitHub 的任务清单。
- 本地成果整理完成后，导入目标公开仓库 [GenAI-powered-learning-platform](https://github.com/Cobblepot2/GenAI-powered-learning-platform)。

## 需求到功能的映射

| 课程方向或要求 | 本阶段原型 | 后续正式系统 |
|---|---|---|
| 软件工程、开发工具与软技能微课 | “把模糊需求变成用户故事”“与 AI 编程代理有效协作”“在团队里做出有依据的产品决定”三门微课 | 根据真实用户反馈扩展内容 |
| 互动学习 | 场景选择、测验、解释反馈、学习进度 | 更丰富的模拟、编程练习与学习活动 |
| 教师编辑与生成课程 | 输入主题后按规则模板生成草稿，编辑、发布到本机目录 | 服务端生成式 AI、审核和共享发布 |
| 个性化课程与学习路径 | 选择课程并查看自己的本机进度 | 根据学习目标和测评提供路径推荐 |
| 导入学生、查看参与情况 | 当前浏览器内的学习事件与进度示例 | 身份验证、班级名单导入、跨用户参与统计 |
| 多原型、反馈与迭代 | 本次原型作为第一版；验证记录模板已准备 | 完成真实验证、整理问题、迭代并保留证据 |
| 公开仓库与个人贡献 | 准备仓库结构、任务与协作流程 | 后续按团队确认的安排认领、提交、评审并留下真实记录 |

## MVP 范围与验收条件

| 项目 | 通过条件 |
|---|---|
| 课程浏览 | 首页能看到三门内置课程，且能进入学习流程 |
| 场景学习 | 至少完成一门课程的选择与测验，并显示相应解释 |
| 进度记录 | 完成活动后进度改变；同一浏览器刷新后仍可查看 |
| 教师草稿 | 输入主题并生成可编辑草稿，界面明确标记为规则模板生成 |
| 编辑发布 | 修改草稿内容后可发布，并从课程目录进入学习 |
| 参与记录 | 学习事件在当前浏览器的教师视图中可见，标明数据范围 |
| 演示可用性 | 常见桌面与窄屏布局可读，主要操作无需开发工具 |
| 真实性 | 不把模板生成功能称为真实 GenAI，不把本机事件称为班级分析 |

实际检查结果由执行者填写或见仓库的验证记录；此表本身不是“已通过”证明。本轮不将登录、真实 AI、云同步、名单导入或正式个性化推荐列入已实现范围。

## 第 8/9 周应带到课堂

1. 1–2 页摘要：问题与目标、当前原型、系统设计、剩余工作。
2. 可运行原型：准备演示入口，并保留静态截图作为网络故障时的备份。
3. 5–10 分钟讨论安排：按 [演示脚本](meeting-script.md) 展示约 6 分钟，再回答问题。
4. 真实进度证据：本次产物、运行结果；团队开展工作后再加入个人提交和用户反馈。

## 后续交付与待确认事项

- 原文件中的 `31/1/2024` 与当前课程安排如何对应，需要教师确认；本计划使用教学周。
- 原文件评分口径中出现 `40%` 与 `35%` 的不一致，需要教师确认，不能自行改写权重。
- 需确认第 8 周还是第 9 周讨论、最终展示时长，以及“课程生成”和“个性化”的最低验收深度。
